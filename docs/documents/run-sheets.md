# Run Sheets

The run sheet is the day-of view your on-site crew lives in. It strips a project down to what matters on the ground — the venue, directions, the site contact, and every service for the day with the crew assigned to each — and presents it as a clean, mobile-first screen with no sidebars or tabs to wade through on a phone.

Unlike the documents you generate as PDFs, the run sheet is a **live web view**. Open it on a phone at the loading dock and it reflects the project's current state — a service that moved an hour, a crew member added this morning — without re-exporting anything.

## When to use a run sheet

- **On site** — the PM or crew lead pulls it up on a phone to see what's happening and who's on each task
- **Multi-day jobs** — services are grouped by date, so a multi-day run reads as one scrollable list
- **Handovers** — point an arriving crew at the run sheet so they can orient themselves without you walking them through the app

## What's on the run sheet

- **Compact header** — venue name and **directions** to the site
- **Services grouped by date** — every delivery, bump-in, bump-out, labour block, and pickup, in date order
- **Crew per service** — the people assigned to each service, listed under it
- **Tappable site contact** — phone numbers are `tel:` links, so the crew taps to call the venue contact without copying the number across

## Opening the run sheet

1. Open the project.
2. Click the **Runsheet** button on the project detail page.

The run sheet opens as its own mobile-friendly page. Bookmark or share the link with the on-site crew so they can reach it directly.

Picture a festival production office running three stages. The site logistics lead opens the run sheet on a tablet: deliveries arriving through the morning, bump-in blocks per stage with the crew on each, and the dock contact one tap away to call. As the day shifts, the sheet stays current — no reprinting, no stale paper.
